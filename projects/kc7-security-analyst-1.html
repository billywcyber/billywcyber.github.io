01 / OVERVIEW

Why I completed this lab

I used this tutorial to practise the investigation loop expected of a junior analyst: define a question, choose the telemetry most likely to answer it, query efficiently, interpret the result and pivot only when the evidence supports the next step.

Publication approach

This page deliberately redacts challenge-specific indicators and answers. The goal is to demonstrate transferable analyst thinking without turning the exercise into an answer sheet.

02 / OBJECTIVE

Investigation objective

Determine whether suspicious user activity can be supported by available security telemetry, correlate the event with related evidence, and document what the data proves—and what it does not prove.

04 / INVESTIGATION METHOD

How I approached the evidence

01
Start with a question

A query should test a hypothesis—not just search a large dataset without purpose.

02
Select the right source

I matched the question to the dataset most likely to record the activity.

03
Filter with known indicators

I narrowed the result set with known values such as a source host, IP or suspicious URL.

04
Interpret before pivoting

I checked what a matching event actually demonstrated before deciding the next investigative step.

05 / QUERY PATTERN

Example KQL structure

A useful pattern in the exercise was to filter outbound network telemetry by a known indicator and a source system. Portfolio values are redacted.

OutboundNetworkEvents
| where url == "<redacted-suspicious-url>"
| where src_ip == "<redacted-source-ip>"

This answers a very specific question: did the source system generate an outbound event to the indicator? The timestamp and surrounding telemetry can then be used for further correlation.

06 / FINDINGS

What the exercise established

✓

Targeted filters reduce noise and make the evidence easier to validate.

✓

A single matching network event is useful evidence, but surrounding context is still required before drawing a broader conclusion.

✓

Each query result should guide the next step rather than create an uncontrolled chain of searches.

07 / LESSONS

What I took away

KQL syntax matters, but investigation quality depends more on knowing what question a query is answering. I also practised documenting enough context that another analyst could follow the reasoning and understand why the evidence changed the investigation direction.

Next step

I will keep this format for future KC7 and blue-team labs so the portfolio becomes a consistent investigation journal rather than a collection of screenshots.
