Overview

Investigation goal

Practise the junior analyst workflow: define a question, select the relevant telemetry, query it efficiently and interpret what the evidence actually proves.

Note

Challenge-specific indicators and answers are intentionally omitted.

Method

Evidence before conclusions

01
Start with a question

Use each query to test a specific hypothesis.

02
Select the right telemetry

Match the question to the dataset most likely to record the activity.

03
Filter and pivot

Narrow the result set with known indicators, then pivot only when the result supports the next step.

KQL example

Focused network-event filtering

OutboundNetworkEvents
| where url == "<redacted-suspicious-url>"
| where src_ip == "<redacted-source-ip>"

The query tests whether a source system generated an outbound event to a known indicator. The timestamp and surrounding telemetry can then be correlated with other evidence.

Lessons

What I took away

•

Targeted filters reduce noise and make evidence easier to validate.

•

A matching event is useful, but context is still required before drawing a broader conclusion.

•

Good investigation notes should make the reasoning easy for another analyst to follow.
