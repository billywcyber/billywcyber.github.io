01 / OVERVIEW

Why I completed this lab

I completed KC7 Security Analyst I — Part 1 to practise the workflow used by a security analyst: form a question, identify the relevant telemetry, query the data, validate the result and pivot into related evidence.

Portfolio approach

This write-up intentionally focuses on investigative reasoning and skills rather than serving as an answer sheet for the KC7 exercise.

02 / OBJECTIVE

Investigation objective

Examine security telemetry to identify suspicious activity, determine whether a user interacted with potentially malicious infrastructure, and build a defensible understanding of what happened from the available evidence.

04 / INVESTIGATION METHOD

How I approached the investigation

01

Start with the investigative question

I identified what needed to be proven from the available evidence instead of searching logs without a clear purpose.

02

Select the relevant data source

I matched the question to the telemetry most likely to contain evidence of the activity being investigated.

03

Filter using known indicators

I used known values such as a source IP or suspicious URL to reduce noise and isolate relevant events.

04

Interpret before pivoting

I checked what each result actually demonstrated, then used that evidence to decide the next query or data source.

05 / QUERY EXAMPLE

Example KQL pattern

One investigation pattern involved filtering outbound network telemetry by a known indicator and source system. The values below are intentionally redacted for portfolio use. 

OutboundNetworkEvents
| where url == "<redacted-suspicious-url>"
| where src_ip == "<redacted-source-ip>"

This query tests whether a specific source system generated an outbound request to the suspicious URL. A matching event can then be correlated with timestamps and other telemetry.

06 / KEY FINDINGS

What the investigation established

The exercise demonstrated how analysts can connect evidence across different datasets and use small, targeted queries to confirm or reject an investigative hypothesis.

✓

Used known indicators to narrow a large telemetry dataset.

✓

Correlated network activity with the surrounding investigation context.

✓

Used query results as evidence for the next investigative step.

07 / LESSONS LEARNED

What I took away

The main lesson was that effective investigation is not just about knowing KQL syntax. The analyst needs to understand what question a query is answering, what a matching event proves, what it does not prove, and which dataset should be examined next.

I also practised documenting enough context that another analyst could understand why a query was run and how the result influenced the investigation.
