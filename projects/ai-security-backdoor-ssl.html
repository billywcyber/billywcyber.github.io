Poisoning Self-Supervised Models by Backdoor Attacks

A five-person research project investigating whether hidden visual triggers can manipulate self-supervised vision models, and whether a label-free detection, filtering and retraining pipeline can reduce that backdoor behaviour.

Overview

Can a model learn a hidden malicious behaviour without obvious damage to normal performance?

Self-supervised learning (SSL) learns useful representations from unlabelled data. That makes it powerful for large-scale computer-vision systems, but it also creates a security question: if a small portion of the training data is poisoned, can the model silently learn an attacker-controlled trigger?

We tested patch-based backdoor attacks across four SSL approaches and then evaluated a defence based on feature-space inspection, suspicious-sample filtering and retraining. ImageNet-10 provided a controlled benchmark, while MS COCO-10 introduced more complex, real-world scenes.

Portfolio summary

The project combined adversarial machine learning, dataset engineering and defensive experimentation. The full academic report is not publicly distributed; this page presents the methodology, selected results and lessons I can discuss in an interview.

Research objective

Evaluate both the attack and the defence.

The primary objective was to evaluate the effectiveness of backdoor attacks against self-supervised models using COCO data, then develop and test a defence capable of detecting and reducing the effect of those hidden triggers.

Attack effectivenessMeasure how reliably a trigger redirects predictions toward an attacker-selected target.
StealthCheck whether the model can retain normal clean-image performance while the backdoor remains active.
Cross-model comparisonCompare BYOL, SimCLR, MSF and MoCo v2 under consistent conditions.
Defence effectivenessMeasure whether filtering and retraining reduce Attack Success Rate without unacceptable clean-performance loss.
Method

End-to-end attack and defence workflow.

01
Collect and prepare data

Build comparable ImageNet-10 and MS COCO-10 datasets, remove duplicates and split data into training and validation sets.

02
Inject a visual trigger

Add a fixed patch trigger to a limited portion of the training data. The experiments used a 10% poisoning rate to keep the attack relatively unobtrusive.

03
Pretrain SSL models

Train BYOL, SimCLR, MSF and MoCo v2 on the poisoned, unlabelled data using ResNet-18 encoders.

04
Measure behaviour

Use linear evaluation and triggered validation images to measure clean performance and Attack Success Rate (ASR).

05
Detect suspicious samples

Extract learned features, cluster embeddings, inspect suspicious patches and score likely poisoned samples.

06
Filter, retrain and re-test

Remove high-risk candidates, retrain on the cleaned dataset, apply i-CutMix and evaluate clean accuracy and ASR again.

Dataset engineering

Making COCO suitable for controlled SSL experiments.

MS COCO is more complex than ImageNet because a single image can contain several objects and classes. To make COCO-10 more comparable with the single-object structure of ImageNet-10, the project used a dominant-object selection pipeline and then removed near-duplicate images.

Dominant-object filteringRetained scenes where the selected class was visually prominent and removed overly crowded images.
80 / 20 splitCreated consistent training and validation partitions for downstream evaluation.
ResNet-18 featuresExtracted deep visual features instead of comparing only raw pixels.
DBSCAN de-duplicationGrouped near-duplicate feature vectors using cosine distance and retained representative images.
Important distinction

DBSCAN was used for dataset de-duplication. The later defence stage used k-means clustering on learned SSL feature embeddings to identify anomalous groups.

Defence

Feature-space inspection without relying on labels.

The defence focused on the representations learned by the poisoned encoder. Triggered images can form unusually compact or anomalous groups because the same patch introduces a repeated visual signal.

A
Feature extraction

Pass training images through the encoder and capture the learned feature vectors.

B
k-means clustering

Group similar embeddings and identify clusters with suspiciously high similarity or unusual distribution.

C
Patch inspection

Extract likely trigger regions from suspicious samples and compare their visual similarity.

D
Candidate filtering

Remove the highest-scoring poisoned candidates to rebuild a cleaner training set.

E
Retraining + i-CutMix

Retrain on the cleaned data and use patch-mixing augmentation to reduce reliance on a single repeated trigger pattern.

Selected results

The defence substantially reduced Attack Success Rate.

For the reported COCO-10 defence experiments using a 10% poison rate, the final PatchSearch + i-CutMix stage reduced ASR across all four SSL models.

MoCo v2ASR: 11.93% → 0.22%
BYOLASR: 7.45% → 0.95%
MSFASR: 7.20% → 0.87%
SimCLRASR: 12.21% → 2.14%

These results supported the central finding that suspicious backdoor behaviour could be reduced using feature-space analysis and data cleaning rather than depending entirely on labelled supervision.

How I explain ASR

Attack Success Rate is the percentage of triggered inputs that cause the model to produce the attacker's intended target behaviour. For this defence evaluation, lower is better.

Challenges & decisions

Adapting the research when compute became the bottleneck.

The original scope proposed much larger datasets. During implementation, the initial dual-feature purification approach took more than 222 hours to reach only 73% completion even on the reduced ImageNet-10 subset. Scaling that method to ImageNet-100 or full COCO was not realistic with the available compute.

01

Reduced the experimental scope to ImageNet-10 and COCO-10 so the project could remain repeatable and complete within resource limits.

02

Revised purification from a dual-feature method to a deep-feature-only ResNet-18 approach, reducing ImageNet-10 purification to roughly an hour.

03

Focused the extension on COCO-10 instead of STL-10 because COCO offered a more complex and less-explored setting for SSL poisoning.

This became one of the most useful project lessons: research quality is not only about running the biggest experiment; it is also about making justified engineering trade-offs, documenting them and preserving a fair comparison.

Key takeaways

What this project taught me about AI security.

Trust requires more than accuracyA model can appear to perform normally on clean inputs while still containing attacker-controlled behaviour.
Data quality is a security controlPurification, duplicate removal and suspicious-sample filtering directly affect model resilience.
Detection can use internal behaviourFeature embeddings can reveal anomalies that are not obvious from raw images alone.
Security experiments need reproducibilityClear metrics, testing logs and consistent conditions are essential when comparing attacks and defences.
