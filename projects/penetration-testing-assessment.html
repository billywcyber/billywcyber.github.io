AUTHORISED LAB · BLACK-BOX ASSESSMENT · 2024

Penetration testing with risk-focused reporting

A controlled black-box assessment of a case-study virtual machine. I moved from reconnaissance to validation, then translated technical findings into CVSS severity, MITRE ATT&CK context and actionable remediation.

EnvironmentControlled lab VM
ToolsNmap · SQLMap · Hydra
FrameworksCVSS · MITRE ATT&CK

01 / SCOPE

Controlled black-box testing

The exercise simulated an external assessment with no starting credentials or internal system knowledge. All activity was performed against a purpose-built case-study virtual machine inside the authorised scope.

Portfolio sanitisation

Specific target addresses, credentials, flags and exploit commands are intentionally omitted. This page demonstrates the assessment process and reporting rather than reproducing an exploitation guide.

02 / METHOD

Reconnaissance → validation → risk → remediation

01
Discovery and probing

Identified live services and the exposed attack surface using network reconnaissance.

02
Vulnerability assessment

Reviewed discovered services and application behaviour for weaknesses that could be validated safely.

03
Controlled exploitation

Validated selected findings within scope to demonstrate potential confidentiality and integrity impact.

04
Risk analysis

Assigned CVSS severity and mapped relevant behaviour to MITRE ATT&CK techniques.

05
Reporting

Converted technical evidence into mitigation recommendations and a prioritised security posture summary.

04 / RISK PRIORITISATION

Severity needs context

9.1example critical CVSS base score
MITREATT&CK mapping for behaviour context
Impactconfidentiality + integrity focus

For high-risk findings, I evaluated exploitability and impact instead of reporting only a tool result. This helped connect technical weaknesses to the likely consequence for the system.

05 / REMEDIATION

Recommendations tied to findings

→

Replace default credentials and enforce unique, complex passwords.

→

Use multi-factor authentication for critical or administrative access.

→

Apply input validation and parameterised queries to reduce SQL injection risk.

→

Patch exposed services and reduce unnecessary attack surface.

→

Use monitoring and prevention controls to identify suspicious web and authentication activity.

06 / ETHICS

Scope and consent are part of the technical work

The assessment was completed in an authorised academic environment. I documented confidentiality, integrity, accountability, scope boundaries and responsible disclosure as part of the report. Those controls are fundamental to professional security testing, not an afterthought.
